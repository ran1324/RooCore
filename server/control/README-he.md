# שרת RooCore — תפעול ומצב

השרת הוקם ב־13 בנובמבר 2026 **ללא Docker**, לפי העדפת המשתמש.

המערכת כוללת שרת Python/FastAPI, תקשורת MQTT עם אימות והרשאות נפרדות לכל בקר,
מסד SQLite וממשק ניהול בעברית. שירותי Linux מעלים אותה אוטומטית ומפעילים את
RooCore מחדש לאחר קריסה. עדכון היישום דורש הפעלה מחדש קצרה שלו בלבד.

## כניסה

פותחים את `https://roocore.saymour.co.il/` ומזינים שם משתמש וסיסמה.
לאחר מכן מקבלים קוד בן 8 ספרות לכתובת המייל הרשומה בחשבון. הקוד תקף
ל־10 דקות ולשימוש אחד בלבד; ללא הקוד לא נפתח חיבור למערכת.

לשחזור סיסמה לוחצים על „שכחתי סיסמה”. הקישור שנשלח למייל תקף לחצי שעה.
שינוי הסיסמה מבטל את כל החיבורים וקודי הכניסה הקודמים. הסיסמה החדשה
צריכה לכלול לפחות 15 תווים. תשתית הדואר וההתראות מתוארת ב־[MAIL.md](MAIL.md).
פרטי האימות והמגבלות נמצאים ב־[AUTHENTICATION.md](AUTHENTICATION.md).
MQTT נשאר מקומי לשרת ואינו מפורסם.
אם סיסמת המנהל אבדה, מתחברים לשרת עם מפתח SSH ומריצים כ־root את
`python3 /usr/local/sbin/roocore-reset-admin-password`. הפקודה מחליפה
לסיסמה אקראית חדשה ומציגה אותה פעם אחת במסוף.

## מה הממשק מציג

הממשק מחולק לשלושה מסכים:

- **סקירה:** חיבור הרובוט, סוללה ומצב מדווח, שירותי השרת ומה נותר להשלים.
- **אירועים:** דיווחים עם זמן ומקור. כברירת מחדל מוצג הרובוט; בדיקות מדומות נמצאות במסנן נפרד.
- **מערכת:** גרסאות התוכנה, זמן הפעלת השירות ופרטי חיבור הבקר.

הנתונים מתעדכנים כל חמש שניות כשהמסך פתוח. אפשר לכבות את העדכון האוטומטי
ולרענן ידנית. ניתוק מוצג במפורש, וערכים שטרם התקבלו נשארים ריקים.
אין בממשק כפתורי הפעלה של הרובוט.

מידע בן 15 שניות ומעלה מסומן כישן. הזמן הזה נועד לתצוגה בלבד, ואינו זמן
עצירה שנבדק ברובוט. מידע שנשמר לפני ניתוק או הפעלה מחדש אינו הופך לחיבור
פעיל בלי דיווח חדש. השרת אינו מסוגל לעצור רובוט דרך חיבור שכבר נותק.

## מה עדיין חסר

קושחת XIAO הנוכחית עדיין אינה מחוברת ל־MQTT החדש. יש להשלים נתיב תקשורת
מוגן מהרשת הביתית, לשלב את הדיווח בקושחה, לאמת את פרוטוקול הרומבה 620
ולבדוק על החומרה את ההתנהגות באובדן רשת, שרת או חשמל. לא בוצעה צריבה,
לא הופעלה חומרה ולא נשלחו פקודות לרובוט. אין מתג תוכנה שפותח את החסימה.

השרת שודרג ל־Ubuntu 24.04.5 LTS. אחרי אתחול בפועל נבדקו מחדש SSH,
RooCore, MQTT, MySQL ו־Nginx. Python של RooCore נשאר בהתקנה נפרדת.
נשמר גם גיבוי חד־פעמי מחוץ לשרת לפני השדרוג; הגיבוי היומי עדיין מקומי,
ולכן יש להשלים גיבוי חיצוני קבוע ותחזוקת עדכוני אבטחה.

הדומיין פעיל דרך Cloudflare Tunnel עם HTTPS. מסך הכניסה וקוד המייל של
RooCore החליפו את שכבת Cloudflare Access הקודמת ואת חלונית Basic.
כניסה ללא אימות לנתוני המערכת נחסמת. הפרטים ב־[CLOUDFLARE.md](CLOUDFLARE.md),
ומגבלות השירותים הישנים ב־[OS_UPGRADE.md](OS_UPGRADE.md).

## פעולות תחזוקה על השרת

```sh
systemctl status roocore mosquitto
systemctl restart roocore
systemctl start roocore-backup.service
journalctl -u roocore -n 50 --no-pager
```

הנתונים נשמרים מחוץ לתיקיית הגרסה. תהליך העדכון בודק את הגרסה החדשה,
מגבה, מחליף רק את קוד היישום, ובמקרה של כשל חוזר לקוד הקודם. המדריך
הטכני מתאר גם שחזור מסד ופרוטוקול התקשורת.

[מדריך טכני](README.md) · [תוצאות ההתקנה והבדיקות](DEPLOYMENT.md).

## משתמשים ומפות בענן — הגרסה החדשה

מסך הכניסה הפנימי מחליף את חלונית Basic הישנה. המשתמש הראשוני הוא `admin`;
הסיסמה הקיימת מיובאת פעם אחת בלבד למאגר גיבובים. אחרי שינוי סיסמה בתוך
המערכת, הקובץ המקומי הישן אינו מתעדכן ואינו מקור לסיסמה החדשה.

מנהל המערכת יכול לצרף בני משפחה דרך ״משתמשים והרשאות״, ליצור קישור אישי
לקביעת סיסמה, ולהגדיר לכל רובוט צפייה, תכנון הפעלה ועריכת מפות. שינוי
הרשאות או ביטול גישה סוגר את החיבורים הקיימים של המשתמש.

ב״מפת הבית״ אפשר ליצור מפת תכנון, לייבא מפה קיימת, לסמן ולערוך חדרים,
אזורים אסורים, קירות וירטואליים ושטיחים ולשמור הכול במסד הנתונים בשרת.
תכנון ניקוי חדר או הגעה לנקודה נשמר כטיוטה עם גרסת המפה. כרגע הוא לא נשלח
לרובוט, והאזורים עדיין אינם הגנה פעילה בבקר. המפה אינה מדידת בית עד שיש
מקור נתונים אמיתי ומאומת. ההבדל מסומן בממשק.
