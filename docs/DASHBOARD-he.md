# אתר מקומי, התקדמות מוקלטת ותחזוקה

2026-11-10 · [English](DASHBOARD.md)

`navigation.server` מציג עכשיו סימולציה או דיווחי רובוט לקריאה בלבד באותו אתר. SQLite שומר דיווחים, סיכומי משימות, שימוש שנצפה ותיעוד טיפול בחלקים לפי המשתמש. השילוב נבדק בנתונים סינתטיים ובשרת דמה מקומי; לא בוצעו חיבור לרובוט, צריבה או אימות פיזי.

## הרצה ללא חומרה

```sh
python3 -m navigation.server --source simulation --port 8766
python3 -m navigation.server --source replay --replay-file tests/fixtures/progress-synthetic.jsonl --store recordings/replay.sqlite3 --port 8767
```

פותחים `http://127.0.0.1:8766` או `http://127.0.0.1:8767`. ברירת המחדל היא סימולציה. הקובץ המצורף מסומן `source: simulation`; זו אינה הקלטה מהרובוט. מצב replay מציג רשומה אחת בשנייה ומסומן כשחזור. אחרי סיום הקובץ הנתונים נעשים ישנים לפי חלון הטריות. השחזור אינו מתחבר לרובוט ואינו ממשיך ניווט. פקודות הסימולציה נדחות במצבי רובוט ושחזור.

השרת נגיש במחשב המקומי בלבד, בודק Host/Origin ואינו מספק העברת פקודות לרובוט. `--store` בוחר מסד מקומי; ברירת המחדל היא `recordings/dashboard.sqlite3`, המוחרג מ־Git. ההקלטות עשויות לכלול מפת בית. כל רשומה מופרדת לפי מקור ומזהה רובוט; אפשר לבחור מסד נפרד להדגמה.

## הגדרת צפייה עתידית ברובוט

הקורא מבצע רק `GET /progress`, עם טוקן שנשמר בתהליך השרת. הכתובת והטוקן אינם מגיעים מהדפדפן, אינם מוחזרים לאתר ואינם נשמרים בהקלטות. הפניות HTTP לכתובת אחרת חסומות. HTTP נתמך עבור נקודת הקצה הקיימת ברשת המקומית; HTTPS אפשרי אם נקודת הקצה תומכת בו. זו אינה הגדרת פריסה מרוחקת.

מגדירים בסביבת תהליך השרת:

| משתנה | משמעות |
|---|---|
| `ROOCORE_ROBOT_URL` | כתובת המקור המדויקת של הרובוט, ללא נתיב, פרמטרים או פרטי הזדהות |
| `ROOCORE_ROBOT_TOKEN` | טוקן הקושחה הקיים, לפחות 24 תווים |
| `ROOCORE_ROBOT_ID` | מזהה שהוגדר לרובוט המסוים |
| `ROOCORE_BATTERY_ID` | מזהה הסוללה המותקנת, שמשתנה בעת החלפה |
| `ROOCORE_WORKLOAD_ID` | תיאור מפורש של רצפה/משימה/תוספות/פרופיל בני השוואה |

שלושת הראשונים נדרשים לבחירת `--source robot`. השניים האחרונים וקובץ `--health-policy /path/to/policy.json` נדרשים לניתוח מגמת הסוללה. בלעדיהם מופיע `unconfigured`, בלי להמציא זהות סוללה או סף אבחון. ברירת המחדל `--stale-after 5` היא חלון טריות ורציפות לתצוגה ולספירת שימוש בשרת, בשניות; היא אינה מגבלה חשמלית. ניתוח הסוללה דורש בנוסף את מגבלת הטריות המפורשת של מדידות הסוללה במדיניות.

מצב הרובוט מומש אך לא נוסה כאן בחומרה. תנאי אימות החיישנים וההפעלה בקושחה נשארים בתוקף. [תיעוד ניתוח הסוללה](BATTERY_HEALTH-he.md) מפרט את שדות המדיניות הנדרשים. הקובץ מכיל רק את השדות האלה. לשחזור בדיקות תוכנה בלבד, אפשר לייצר את **מדיניות הבדיקה הסינתטית, שאינה מכוילת**:

```sh
python3 -c 'import json; from dataclasses import asdict; from tests.test_battery_health import policy; print(json.dumps(asdict(policy())))' > recordings/synthetic-policy.json
```

זה אינו קובץ המלצות לסוללה אמיתית. לא מצורפת מדיניות סוללה מכוילת.

## חוזה הדיווח

`GET /api/state` שומר את שדות המפה של הסימולציה ומוסיף `source`,‏ `read_only`,‏ `identity`,‏ `freshness`,‏ `progress`,‏ `battery_health`,‏ `history` ו־`maintenance`. הנתיבים `/api/health`,‏ `/api/history` ו־`/api/maintenance` מחזירים את החלק המתאים. `/api/checkpoint` מייצא נקודת המשך של הסימולציה או את דיווח הקושחה האחרון לקריאה בלבד; לפני קבלת דיווח מוחזר HTTP 409.

`/progress` בגרסה 1 כולל זהות אתחול/משימה/מפה, מונים, זמן MCU, מפה חסומה בגודלה, כיסוי מרכזי/צדי, מיקום ומצב. `pass_index` מתחיל באפס; `pass` הוותיק מתחיל באחת. הקורא בודק מבנה וסדר מונים, דורש מזהה מפה חדש אם הגאומטריה השתנתה, מפריד אתחולים, מקפיא סמן כשאין מיקום אמין ומנתק קווים בפערים או בשינוי מסגרת. תזוזה של יותר מתא מפה אחד בין דיווחים מתחילה קו חדש; זה כלל תצוגה, לא מגבלת תנועה פיזית.

אחוז הכיסוי מתייחס למעבר המברשת המרכזית על **רצפה שנצפתה**, במעבר הנוכחי. רצפה לא ידועה אינה נספרת כמוכרת. מברשת צד בלבד ושטח שלא הושלם נשארים נפרדים. סיום התוכנית הוא שדה נפרד ואפשרי גם כשנשארה רצפה מוכרת שלא כוסתה. `reported_active_s` הוא זמן המשימה הפעיל של הקושחה, כולל חזרה/עגינה/התאוששות וללא טעינה/השהיה; אין להציגו כזמן ניקיון טהור. `reported_cleaning_s` נשאר null כשאין מונה מתאים. מוני זמן הפקודה שנצפה אינם כוללים פערי דיווח, ואינם מדידת סיבובים, בלאי או כל חיי הרובוט.

ניתוח הסוללה משתמש ב־`battery_sample_ms` וב־`battery_valid`, ובאירוע סיבת חזרה מאומת המקושר למשימה, לאתחול ולזמן. קוד סיבה כללי אינו מוכיח חזרה בגלל הסוללה. דיווח שמור שחוזר על עצמו אינו מחדש טריות. ניתוקים נשמרים כדי ששחזור ההיסטוריה ישמור את פסילות ההשוואה. זהות תצפית סרק עם `mission_active: false` אינה יוצרת משימת ניקיון או קטע להשוואת סוללה. ניתוח בשחזור מסומן כהיסטורי; נתון סינתטי אינו יוצר התראת סוללה אמיתית.

## תחזוקה ומקורות

`POST /api/maintenance/settings` מקבל `{"pets":true}`. `POST /api/maintenance/event` מקבל למשל:

```json
{"part":"filter","action":"replaced","date":"2026-11-10","identity":"זיהוי חלק אופציונלי לפי המשתמש"}
```

מפתחות החלקים: `bin`,‏ `filter`,‏ `main_brushes`,‏ `front_caster`,‏ `side_brush`,‏ `cliff_sensors`,‏ `charging_contacts`. הפעולות הן `installed`,‏ `cleaned`,‏ `replaced`,‏ `snoozed`. התקנה/החלפה מאפסת גיל ונקודת ייחוס לשימוש; ניקוי אינו מאפס גיל החלפה. רישום מאוחר של אותה פעולה יכול לתקן תאריך תוך שמירת האירועים הקודמים. מקור התאריכים וזהות החלק הוא המשתמש. תאריך התקנה חסר נשאר לא ידוע, ותאריך ישן אינו משחזר שימוש שלא נמדד. הפעולות האלה משנות רק אחסון מקומי, גם במצב רובוט.

התזכורות מקשרות ל[טבלת iRobot לסדרות הוותיקות](https://support.irobot.co.uk/articles/en_GB/Knowledge/11179) ול[הוראות סדרת 600](https://homesupport.irobot.com/articles/en_US/Knowledge/8247). עם חיות מחמד, ניקוי שבועי של הפילטר והמברשות המרכזיות הופך לפעמיים בשבוע; תזכורת אחרי שלושה ימים היא קירוב תזמון של RooCore. טווחי החלפה נשמרים כטווחים: בדיקת מברשות מתחילה בשישה חודשים וסוף החלון הוא שנים־עשר חודשים. אין מרווח החלפה מומצא לחלק שלא קיבל כזה בטבלה. אין לשטוף פילטר; טיפול במברשות כולל מיסבים. `wear_percent` תמיד null.

## בדיקות

```sh
python3 -m unittest tests.test_monitor tests.test_battery_health -v
```

נבדקו הפרדת כיסוי מסיום תוכנית, מיקום חסר, נתונים ישנים/כפולים/מאוחרים, מסגרת מפה, גלישת מונים, סרק, שמירת ניתוקים, ראיות סוללה מאומתות, היסטוריה וחלקים לפי מקור, הפרשי מוני סימולציה ואיסור העברת פקודות דרך שרת דמה מקומי. אלה אינן בדיקות פיזיות של סוללה, חיישנים, מגע עגינה או טעינה.
