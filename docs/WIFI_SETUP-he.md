# הגדרת Wi-Fi פרטית — XIAO ESP32S3

מצב: קוד משולב, בדיקות מארח/דפדפן מדומה ובניית קושחה; ללא צריבה או בדיקה בבקר אמיתי. המשך ל[חיבור לענן](CLOUD_STREAM-he.md). דגלי אימות החומרה נשארו כבויים.

## הגדרה ראשונה

1. בקובץ הפרטי נדרשת `ROO_SETUP_AP_PASSWORD` ייחודית ונפרדת, 12–63 תווי ASCII מודפסים ללא רווחים. היא שונה ממפתח ההתקן ומהסיסמה לרשת הבית. בדוגמה הציבורית היא ריקה ולכן לא תיפתח רשת הגדרה. ניתן להשאיר את שם וסיסמת רשת הבית ריקים.
2. אימות ראשוני נעשה ב־USB בלבד, כשהבקר מנותק לחלוטין מהרומבה, מהצמה ומכל מקור מתח אחר. יש לזהות לוח/פורט, תמונה ודרך שחזור לפני צריבה. מסמך זה אינו דיווח על צריבה ואינו פקודת צריבה מוכנה להרצה.
3. אחרי שהתמונה המתאימה פועלת, בהיעדר רשת שמורה או רשת בקובץ, הבקר מבקש מצב הגדרה. ליבת הבקרה מאשרת רק במצב פנוי/מושהה/הושלם. הכנת USB ללא commissioning דורשת גם היעדר חיבור רובוט מאומת והיעדר בעלות תנועה. תוכנה אינה יכולה להוכיח ניתוק פיזי.
4. מתחברים ל־`RooCore-Setup-xxxxxx` עם סיסמת **רשת ההגדרה**, ופותחים ידנית **http://192.168.4.1/setup**. דף HTTP מקומי זה פועל ברשת זמנית המוגנת ב־WPA2-PSK/CCMP ומאפשרת לקוח אחד. אתר הניהול נשאר ב־HTTPS.
5. סורקים ובוחרים רשת 2.4GHz, או מזינים שם ידנית לרשת מוסתרת; מזינים סיסמה ובוחרים חיבור ושמירה. שם הרשת מוגבל ל־32 בתים. סיסמה ריקה לרשת פתוחה, או 8–63 תווי ASCII מודפסים. רשת Enterprise ומפתח PSK גולמי בן 64 ספרות אינם נתמכים בטופס. נבדק חיבור לרשת המקומית, לא זמינות האינטרנט/הענן.
6. רק אחרי חיבור מוצלח נשמרת רשומת NVS אחת עם גרסה וסכום ביקורת ונקראת בחזרה. הסיסמה אינה מוחזרת ב־API או בלוג הסריאלי. חיבור שנכשל אינו מחליף את הרשומה השמורה; כשל כתיבה/קריאה חוזרת מוצג כשגיאת שמירה. אובדן מתח בזמן החלפה עשוי להשאיר רשומה שלמה ישנה או חדשה. סכום הביקורת אינו הצפנה או הגנה מפני חילוץ פיזי של Flash.
7. אחרי הצלחה מחזירים את הטלפון לרשת הבית ופותחים `https://roocore.saymour.co.il`. רשת ההגדרה נסגרת אחרי חלון תשובה בן שמונה שניות. חלון הגדרה מוגבל לחמש דקות וניסיון חיבור ל־25 שניות — תקציבי תוכנה לממשק. הצלחה או תום הזמן אינם מתחילים/מחדשים ניקוי.

## שינוי רשת

כשהקושחה כבר פועלת והרובוט כבר עומד, מחזיקים **BOOT** שלוש שניות ומשחררים. אין להחזיק BOOT בזמן איפוס/הדלקה: הוא בוחר מצב הורדה של ROM. ב־XIAO ESP32S3 המדויק, BOOT הוא **GPIO0**; פין המחבר **D0 הוא GPIO1** ומשמש לתקשורת OI, ואינו כפתור ההגדרה. אין חוט חדש. [מפת היצרן והוראות BOOT](https://wiki.seeedstudio.com/xiao_esp32s3_getting_started/).

בקשה בזמן ניקוי, יציאה מהעמדה, פעולה מקורית או OTA נדחית. ברובוט שעבר commissioning נדרשים אנקודרים מאומתים וטריים עם חלון תוכנה קיים של שתי שניות ללא שינוי, OI במצב Passive ונתוני בטיחות טריים, יציאות ניקוי כבויות ורף מתח שמירת Flash מאומת. אובדן התנאים סוגר את ההגדרה. זו אינה הוכחת עמידה פיזית עצמאית. הכפתור, סריקת RF, פעולה לצד רשת הבית והתאוששות NVS מאובדן מתח עדיין דורשים בדיקה פיזית.

## בידוד ופעולה ללא אינטרנט

- ניתוק אינטרנט או Wi-Fi רגיל אינו פותח מצב הגדרה. הבקר מנסה להתחבר לרשת הידועה ושומר את המשימה וההגבלות המקומיות.
- מצב הגדרה מחזיק את בקר התנועה, חוסם בקשות פקודה מקומיות ומשהה שידור לענן. טיפול HTTP ו־Wi-Fi מחוץ לליבת הבקרה. סגירת ההגדרה מסירה רק את ההחזקה שלה; המשך משימה דורש פקודה מפורשת נפרדת.
- ההגדרה אינה משנה מפתח התקן, כתובת שרת, קושחה, דגלי commissioning, מפה, אזורים אסורים או דרישת השמירה שלהם. מרחב NVS נפרד; אין פירמוט LittleFS.
- נתיבי ההגדרה דורשים AP פעיל, חיבור לכתובת ה־AP ומקור בתת־הרשת שלו, Host של ה־IP המדויק, וב־POST גם Origin מדויק ו־nonce אקראי חדש בן 128 סיביות. גוף בקשת החיבור הרגיל נקלט במאגר קבוע של 512 בתים; שדות כפולים/לא מוכרים וקידוד אחוזים לא תקין נדחים. אין שמירת מטמון, הטמעה ב־frame או משאבים חיצוניים. שמות רשת מוכנסים כטקסט ולא כ־HTML.
- אין שרת DNS להגדרה, העברת DNS, NAT או פתיחת פורטים בנתב הבית. יש להקליד את הכתובת המקומית המפורשת. אימות LAN/OTA נשאר נפרד. בדיקות מארח אינן מוכיחות בידוד RF או זמני פעולה פיזיים.

האימות כולל גבולות/שיבוש רשומה, גלישת שעון, הדף האמיתי עם שרת מדומה ובניות ברירת מחדל/תצורה סינתטית. ראו [רשומת הבדיקות](assembly/VALIDATION.md). [API Wi-Fi של Espressif](https://docs.espressif.com/projects/arduino-esp32/en/latest/api/wifi.html); חתימות מדויקות נבדקו במקור Arduino ESP32 המותקן **3.3.12**.
